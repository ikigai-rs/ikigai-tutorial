# Resource names the `ikigai` CLI resolves — the book's claim about somebody else's host.
#
# The book prints two kinds of resource name, and they answer to different authorities:
#
#   * names in Rust examples resolve in a host THIS REPOSITORY builds, so the URN gate
#     (`crates/book-urns`) checks them against `hello_camel::space()` and
#     `loadable_module::host_space()` — real spaces, checked by construction;
#
#   * names in `ikigai …` shell examples resolve in the CLI, which is a different
#     repository on a different release schedule. Nothing this workspace compiles can
#     confirm one. This file is where the book states what it believes, so that the
#     belief is at least written down in one place and checkable by one command.
#
# Format: one entry per line, `#` starts a comment. A trailing `*` makes the entry a
# prefix — `urn:file:*` covers `urn:file:{path}`, `urn:file:notes.txt` and the rest of a
# templated family whose tail is caller-supplied.
#
# ⚠ HOW TO VERIFY, and why the gate cannot do it for you. CI has no `ikigai` binary and
# no way to get a trustworthy one, so the always-on test only checks that every shell
# name in the book appears below. That catches a typo and an invented name; it CANNOT
# catch this file having gone stale against a newer CLI. The check that can is a probe,
# and it is a test in this workspace marked `#[ignore]` because it needs a binary:
#
#     cargo install ikigai-cli --locked          # or have one on PATH already
#     cargo test -p book-urns -- --ignored --nocapture
#
# Run it when you change this file, and when the CLI releases. Verified against
# ikigai-cli 0.1.18 on 2026-09-08, the front-door entries included.

# The function library, `ikigai-fn` 0.2.0, bound into the CLI's base space.
# (`toUpper` and `reverseList` are verb phrases and break the naming convention the book
#  teaches in "Binding, and a host of your own"; they are named here as they are, not as
#  they should be.)
urn:iki:fn:toUpper
urn:iki:fn:reverseList
urn:iki:fn:compose
urn:iki:fn:conditional
# The same library's demo endpoints, which the grammar chapter's map and fork lines use,
# and the compose shape the CLI's host binds for its own demo.
urn:demo:split
urn:data:page

# The Lisp engine the grammar chapter names in passing: a line starting with `(`.
urn:lisp:eval

# The coreutils-analog text endpoints (`ikigai-text`), named as a family by the
# repository map. Probed as `urn:text:wc`, `urn:text:head`, `urn:text:sort`.
urn:text:*

# The kernel's own self-description resources. These are intercepted by the kernel rather
# than bound in a space, so `list` does not show them; `source` does.
urn:kernel:catalog
urn:kernel:actions

# The golden-thread and cache resources "What resolution buys you" drives from a REPL:
# `sink urn:kernel:cut <thread>` cuts a thread by hand, `urn:kernel:threads` lists every
# thread ever cut with its generation, `urn:kernel:cache` lists what is cached. All three
# are kernel-intrinsic like the two above, and `source`/`sink` reach them while `list`
# does not.
urn:kernel:cut
urn:kernel:threads
urn:kernel:cache

# What the CLI's scheduler is, and — the reason the configuration chapter prints it — which
# of flag / config / env / default decided.
urn:kernel:scheduler

# The file workspace, a URI template over the CLI's jail. The tail is a path the caller
# chooses, so this has to be a prefix entry.
urn:file:*

# ── Building endpoints ────────────────────────────────────────────────────────
#
# The linked-data toolkit the CLI links natively (`ikigai-rdf`, `ikigai-sparql`): a
# transreptor between RDF syntaxes, and SELECT over any graph the kernel can resolve —
# the two the graph-face and transreption chapters drive from a shell.
urn:rdf:transrept
urn:sparql:select

# ── Part III — Beyond one host ────────────────────────────────────────────────
#
# ⚠ These are all names the CLI's OWN host binds, which is what this file may claim.
# Two of them are also served by other processes the book names — `urn:repo:status` by
# ikigai-dev over a socket, `urn:llm:*` by whatever a peer is mounted at — and that is
# precisely the point of those chapters. It is not what makes the entry true here: an
# entry earns its place by resolving in a plain `ikigai`, with no mount and no server.

# The dev seam. `ikigai-dev` serves this too, over a socket; the omnibus binary also
# links `ikigai-repo`, which is why the book's `--connect` example can be probed
# against a plain CLI.
urn:repo:status

# The manifold projected as callable Lisp — what `ikigai-refresh-aliases` resolves,
# and what makes an editor's command surface unable to drift.
urn:lisp:aliases

# The LLM face: one front grammar over pluggable backends. `urn:llm:{provider}:ask`
# is deliberately NOT listed — which providers exist is the reader's own llm.json,
# so the book declares that name an illustration rather than claiming it.
urn:llm:ask
urn:llm:models
urn:llm:config

# The selection funnel: deterministic narrowing, then a model only for the residual,
# then a pre-flight validation of the arguments against the declared contract.
urn:agent:select
urn:kernel:validate
