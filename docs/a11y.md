# The ikigai Book — accessibility assessment (WCAG 2.2 AA)

Assessed 2026-09-09 on the **built** book (`books/ikigai/book/`, mdbook 0.5.4, 35 pages
plus `print.html`), page by page, with three instruments: a read of the markup and CSS
mdbook generates, `crates/book-a11y` (contrast since PR #5; structure since this pass),
and axe-core 4.10 over a jsdom of every page with the book's scripts run (`a11y/axe.mjs`).
Every finding is named by its success criterion. Where a criterion is not mentioned, it
was checked and nothing was found — or it does not apply (there is no audio, video,
time limit, flashing content, drag interaction or authentication anywhere in the book).

## Findings, by criterion

| SC | Level | Finding | Where | Fixed by |
|---|---|---|---|---|
| 2.1.1 Keyboard | A | The sidebar toggle is a `<label for>` driving a `display: none` checkbox: nothing in the pair takes focus, so a keyboard user cannot open or close the table of contents on a narrow screen | every page (mdbook template) | `js/a11y.js`: the label gets `role="button"`, `tabindex="0"`, Enter/Space toggles the checkbox |
| 4.1.2 Name, Role, Value | A | mdbook's script writes `aria-expanded` onto that label, an attribute a label may not carry (axe: `aria-allowed-attr`) | every page | same repair — with `role="button"` the attribute is allowed, and it is kept true to the checkbox |
| 4.1.2 Name, Role, Value / 3.3.2 Labels or Instructions | A | The search box (`<input type="search" id="mdbook-searchbar">`) has a placeholder and no label: an unnamed edit field | every page | `js/a11y.js`: `aria-label` from the placeholder text, so what is heard is what is seen |
| 1.3.1 Info and Relationships | A | The same input's `aria-describedby="searchresults-header"` names an id that does not exist (`mdbook-searchresults-header` does), so the description is lost | every page | `js/a11y.js`: re-pointed at the element that exists |
| 2.5.3 Label in Name | A | The Run cell's button had `aria-label="Run in this page"`; once its visible text read "Run again", the name no longer contained the label — a speech-input user saying what they see would miss it | Run cells (M4.0) | `js/run.js`: no `aria-label`; the visible text is the name, the command pane is `aria-describedby` |
| 4.1.3 Status Messages | AA | The cell's caption ("running…", "from the kernel in this page", "the in-page kernel did not load (…)") was outside the `aria-live` region, so the status of the action — and the fallback being a fallback — was never announced | Run cells | `js/run.js`: caption and output pane are one `role="status"` `aria-live="polite"` `aria-atomic="true"` region |
| 3.3.2 Labels or Instructions / 4.1.2 | A | The cell's command became an editable `<textarea>` (M4.1); it carries a visible `<label>` and an `aria-describedby` explaining the keys (Enter runs, Shift+Enter adds a line, Reset restores) | Run cells | `js/run.js` |
| 2.4.2 Page Titled | A | Two chapters were both titled "Exercises", so two pages shared a `<title>` and the tab, history and bookmarks could not tell them apart | Part I and Part III | prose: "Exercises: getting started" and "Exercises: beyond one host" |
| 1.3.1 Info and Relationships | A | The status chapter's summary table had an empty header row (`\| \| \|`): header cells with no text (axe: `empty-table-header`, best practice) | `modules/status.md` | prose: `piece` / `state` |
| 2.4.7 Focus Visible | AA | `<details><summary>` hints have no author focus style; the browser default applies, which passes, but differs from the ring the skip link and Run buttons draw | exercises | `css/a11y.css`: `summary:focus-visible` gets the same ring — consistency, not a failure |
| 1.3.1 (best practice: `landmark-unique`) | — | Two `<nav aria-label="Page navigation">` per page (inline and wide-screen), indistinguishable in a landmark list | every page | `js/a11y.js`: the second is "Page navigation (wide screens)" |
| 2.3.3 Animation from Interactions | AAA | The search box's loading spinner (`#fa-spin`, 2s infinite rotation) is not guarded by `prefers-reduced-motion`; mdbook guards its footnote highlight | every page | `css/a11y.css`: `animation: none` under reduced motion — beyond AA, cheap |
| 1.4.3 / 1.4.11 Contrast | AA | 22 pairs below the floor across the five themes — found and repaired in PR #5, gated since | all themes | `css/a11y.css` (unchanged by this pass; the gate re-measured 14 pairs × 5 themes green) |

## Checked and sound (no change)

- **3.1.1 Language of Page** — `<html lang="en">` on every page.
- **2.4.1 Bypass Blocks** — the skip link `js/a11y.js` adds (PR #5), gated by its target id.
- **1.3.1 / 2.4.6 Headings** — one `h1` in `<main>` per page, no level skipped, on all 35 pages. mdbook's second `h1` (the book title in the menu bar) is upstream's template and deliberately left alone (README, "Left alone, deliberately").
- **1.1.1 Non-text Content** — the book has no `<img>`; the ⚠ markers are text glyphs, announced as "warning sign" and always followed by words, so nothing rests on the glyph alone (1.3.3 Sensory Characteristics, 1.4.1 Use of Color).
- **1.4.1 Use of Color** — the cells' cache verdicts (`[cached]`, `[computed]`) are text; no pass/fail state anywhere is color-only.
- **2.4.4 Link Purpose** — no empty link text, no "here"/"click here"/"this"/"more" anywhere; every cross-reference names its chapter (the chapter-number gate from PR #4 already forbids `[chapter N]`).
- **4.1.2** on mdbook's chrome — theme buttons (`role="menuitem"`, visible text), search toggle and theme toggle (`aria-label`), copy-to-clipboard buttons (`aria-label="Copy to clipboard"`, injected by mdbook's script; visible only to axe).
- **1.4.10 Reflow / 1.4.4 Resize Text** — mdbook's layout reflows to 320px; the cells use `white-space: pre-wrap` and `overflow-wrap: anywhere`, so a long Turtle line wraps rather than scrolls.
- **2.4.11 Focus Not Obscured (Minimum)** — mdbook sets `scroll-margin-top` for `:target` under its sticky menu bar; tabbing through a chapter never landed under the bar in the pages tried.
- **3.2.3 / 3.2.4 Consistent Navigation and Identification** — mdbook's chrome is identical on every page; every Run button reads "Run" then "Run again".
- **1.3.4 Orientation, 1.3.5 Identify Input Purpose, 2.5.7 Dragging, 3.3.7 Redundant Entry, 3.3.8 Accessible Authentication** (WCAG 2.2 additions) — nothing in the book is orientation-locked, collects personal data, is dragged, re-asks for input, or authenticates.

## What the gate now refuses

`./scripts/test-books.sh` runs `book-a11y` after every build, and it exits non-zero on
any of these, each reported as `SC <number> <name> — <detail>`:

- `<html>` without a non-empty `lang` (3.1.1); a page without a non-empty `<title>`, or
  two pages sharing one (2.4.2; `index.html` is the first chapter's alias and exempt);
- not exactly one `<h1>` inside `<main>`, or a heading level that skips (1.3.1);
- an `<img>` with no `alt` attribute at all — `alt=""` is decorative and allowed (1.1.1);
- a link with no text, `aria-label` or `title`, or whose text is "here", "click here",
  "this", "link", "more" or "read more" (2.4.4);
- a duplicate `id`; an `aria-controls`, `aria-describedby` or `aria-labelledby` naming an
  id that is not on the page (4.1.2 / 1.3.1);
- a `<table>` with no `<th>` (1.3.1);
- a `<button>` with no accessible name; an `<input>` with no `<label for>`, `aria-label`
  or `aria-labelledby` — a placeholder is not a name (4.1.2);
- a runnable cell without `data-cmd`, or without its `<pre class="ikigai-run-expected">`
  — the text its status region falls back to (4.1.2 / 4.1.3);
- a contrast pair below 4.5:1 for text or 3:1 for a component, in any theme (1.4.3 / 1.4.11);
- the skip link's target id gone from the page (2.4.1).

The two search-box faults are in mdbook's own markup and are repaired at load by
`js/a11y.js`; the gate credits them **only while that script still contains each repair**
(`book_a11y::structure::A11Y_JS_REPAIRS`). Delete the repair and the build is red.

`pages.yml` runs the second instrument before anything is uploaded: axe-core over a jsdom
of every page with the scripts run and every Run button pressed once, gating on WCAG 2.x
A/AA rules; best-practice rules are survey-only. It is what sees the sidebar toggle, the
copy buttons, the cells, and the search repairs — the parts a static read cannot.

## What only a human can still judge

- **Reading order and plain language** (1.3.2, 3.1.5). The prose is long-form and
  argumentative by design; nothing measures whether a paragraph lands.
- **Link purpose beyond the generic phrases** (2.4.4). "the chapter above" passes the
  gate; whether it is clear is a reviewer's call.
- **Target size** (2.5.8, new in 2.2). mdbook's menu-bar icon buttons are roughly 24 CSS
  px, the minimum; jsdom has no layout, so neither instrument measures it. Read as
  "probably meets, not proven".
- **Focus not obscured under the sticky bar on every page** (2.4.11) — sampled, not
  exhaustive.
- **The wasm path of the Run cells** — axe sees the fallback path (jsdom cannot import the
  module); the kernel path was verified by hand in a browser (PR #11 and this pass:
  pointer click runs a cell; the status region announces the result; Enter in the
  command field runs it; the history list under the cell is an ordered list with a name).
- **mdbook's second `h1` per page** — a best practice, left alone on purpose; the reasons
  are in the README.

## How to re-run it

```bash
./scripts/test-books.sh                          # mdbook test + contrast + structure
cargo run -p book-a11y -- books/ikigai --survey  # every pair and every page
cd a11y && npm ci && node axe.mjs ../books/ikigai/book --survey
```
